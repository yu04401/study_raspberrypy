08超音波パーキングセンサー

5V で動くセンサを安全につなぐための分圧回路を設計し、パルス幅から距離を計算します。

  • ⏱ 目安 90分
  • 🔧 回路 + 💻 コード
  • 📚 電圧レベル変換・パルス幅計測・タイムアウト・中央値フィルタ

🎯 つくるもの

超音波センサで距離を測り、近づくほど LED が速く点滅するパーキングセンサーを作ります（10cm 未満で点灯、100cm 以上で消灯）。

🧰 使う部品

  • 超音波センサ（HC-SR04 / Ultrasonic Ranging Module）×1
  • 抵抗 1kΩ×3
  • 抵抗 220Ω×2
  • 赤色LED×1

共通で使うもの: Pico 2 W、ブレッドボード、ジャンパワイヤ、USB ケーブル。

📌 この課題のポイント

  • HC-SR04 は Trig に 10µs のパルスを入れると、音が往復した時間だけ Echo を High にする。
  • 5V の信号を 3.3V のマイコンに入れるときは、分圧などで電圧を下げるのが基本。
  • センサが壊れたり外れたりしても固まらないよう、待ちループには必ずタイムアウトを付ける。
  • 距離センサには外れ値がつきもの。平均より中央値のほうが外れ値に強い。
  • 測定と LED 点滅をタイマ割り込みで分離すると、それぞれを独立に作れる。

STEP 1回路課題

HC-SR04 は 5V 動作のセンサです。Echo の 5V 出力を安全に Pico へ入れる方法を設計しましょう。

  1. HC-SR04 を VBUS（5V）で動かすと、Echo は 5V で出力されます。そのまま Pico の GPIO につないでもいい？
  2. キットの抵抗（220Ω / 1kΩ / 10kΩ）だけで、Echo を 3.3V 以下に落とす分圧回路を設計しよう。USB の 5V は最大 5.25V 程度まで上がりうることも考えて。
  3. 逆向き（Pico → センサ）の Trig は、3.3V の出力で 5V のセンサを動かせる？
  4. 分圧に 10kΩ クラスを使う場合と 1kΩ クラスを使う場合の違いは？
分圧の式: Vout = Vin × R2 ÷ (R1 + R2)。R1 が信号側、R2 が GND 側。
抵抗は直列につなぐと足し算できます（1kΩ + 1kΩ = 2kΩ、1kΩ + 220Ω = 1.22kΩ）。
5V 系ロジックの入力は、だいたい 2V 以上を High と判定します。
ピンには小さな容量（数 pF）があり、抵抗と組み合わさると信号の立ち上がりが鈍ります（RC 時定数）。

問いの答えと解説

  1. 避けるべきです。RP2350 のデジタル GPIO は「通電中なら 5V に耐える（5V トレラント）」仕様ですが、
    • Pico の電源が入っていない・立ち上がり途中のときは保護されない
    • ADC ピン（GP26〜29）は対象外
    • 初代 Pico（RP2040）では不可。同じ回路を流用すると壊れる
    という条件付きです。分圧しておくのが安全で、移植性も高い設計です。
  2. 例: R1 = 1kΩ + 220Ω（1.22kΩ）、R2 = 1kΩ + 1kΩ（2kΩ）。 5.0V × 2 ÷ 3.22 ≒ 3.11V、5.25V でも ≒ 3.26V に収まります。 よく見る R1 = 1kΩ、R2 = 2kΩ の組み合わせだと 5V で 3.33V、5.25V で 3.5V と、少し余裕がありません。
  3. 動かせます。3.3V は 5V 系入力の High 判定（約 2V）を十分超えます。
  4. 10kΩ クラスは消費電流が小さい反面、ピンの容量と合わせて立ち上がりが鈍ります。1kΩ クラスは約 1.5mA 流れますが、µs 単位の計測でも波形がきれいです。今回は時間を測るので1kΩ クラスが向いています。
基板に「3.3V–5V」などと書かれた 3.3V 対応品（HC-SR04P など）なら、VCC を 3V3 にして分圧なしで直結できます。手元のモジュールの表記を確認しましょう。

⚠ ハマりどころ

  • 分圧の R1 と R2 を逆にすると、GP17 に 5V × 2/3.22 ではなく約 1.9V しかかからず、High を読めなくなります（安全側ですが動きません）。
  • センサの前に配線やブレッドボードがあると、それに反射して近い距離が出ます。

STEP 2コーディング課題

距離を測る部分と、LED を点滅させる部分を分けて作ります。

要件

  • Trig に 10µs のパルスを出し、Echo の High の長さを µs で測る
  • Echo 待ちには 30ms のタイムアウトを付け、超えたら「測定不能」とする
  • 5 回測って中央値を使う。測定の間は 60ms 以上あける
  • 気温 25℃ として音速を補正し、cm に換算してシリアル表示する
  • LED の点滅は 10ms ごとの繰り返しタイマで行う: 10cm 未満 = 点灯、10〜100cm = 距離×5ms 周期で点滅、それ以上 = 消灯
音速 = 331.5 + 0.6 × 気温 [m/s]。25℃ で約 346.5m/s = 0.03465cm/µs。往復なので 2 で割ります。
パルス幅は time_us_64() を使って「High になった時刻」と「Low に戻った時刻」の差で測ります。while の中で経過時間をチェックすればタイムアウトになります。
add_repeating_timer_ms(10, callback, NULL, &timer)。コールバックが true を返すと繰り返します。timer 変数はタイマが動いている間ずっと有効なスコープに置くこと。
メインとタイマ割り込みで共有する「点滅周期」は volatile に。
中央値は配列を qsort して真ん中を取るのが簡単です。

解説

  • measure_echo_us() はタイムアウト付きのブロッキング計測です（最大 60ms ほど止まる）。LED をタイマ割り込み側で点滅させているので、計測中も点滅は乱れません。
  • 点滅周期を UINT32_MAX（常時点灯）や 0（消灯）という特別な値で表すのは、状態を 1 つの変数で渡す簡単な方法です。
  • 失敗した測定は中央値の計算から除外しているので、5 回中 1〜2 回の失敗なら結果に影響しません。

⚠ ハマりどころ

  • タイムアウトのない while (!gpio_get(ECHO_PIN)); は、配線が外れた瞬間に永久ループになります。
  • 測定間隔が短すぎると、前回の音の残響を拾って近い距離が出ます。
  • repeating_timer_t をローカル変数にした関数から抜けると、タイマが壊れたメモリを参照します（今回は main 内なので OK）。
