04可変抵抗でLEDの明るさを調整

アナログ値を読み取る ADC を使い、つまみの角度で LED の明るさを変えます。

  • ⏱ 目安 45分
  • 🔧 回路 + 💻 コード
  • 📚 ADC・分圧・移動平均

🎯 つくるもの

可変抵抗（ポテンショメータ）を回すと LED の明るさがなめらかに変わり、シリアルに電圧値が表示されるようにします。

🧰 使う部品

  • 可変抵抗 10kΩ（Potentiometer）×1
  • 赤色LED×1
  • 抵抗 220Ω×1

共通で使うもの: Pico 2 W、ブレッドボード、ジャンパワイヤ、USB ケーブル。

📌 この課題のポイント

  • ADC（A/D変換器）は 0〜3.3V を 0〜4095 の整数（12bit）に変換する。
  • 可変抵抗は「中点が動く分圧回路」。両端に電圧をかけ、中点の電圧を読む。
  • ADC に使えるのは GP26〜GP28 の 3 本だけ（GP29 は Pico 2 W 内部で使用）。入力は 3.3V を超えてはいけない。
  • ADC の値は数カウント揺れる（ノイズ）。平均化で安定させる。

STEP 1回路課題

可変抵抗を ADC0 に、LED を課題01と同じ GP15 につなぎます。

  1. 可変抵抗の 3 本の脚の役割は？ 両端と真ん中は、それぞれどこにつなぐ？
  2. Pico 2 W で ADC 入力として使えるピンはどれ？ 物理ピン番号も。
  3. 可変抵抗の片側を普通の GND ではなく AGND（物理ピン33）につなぐのはなぜ？
  4. 可変抵抗の端を 3V3 ではなく VBUS（5V）につないではいけない理由は？
両端の間は常に 10kΩ。つまみを回すと、真ん中の脚（ワイパ）が抵抗体の上を移動します。
Pico のピン図で「ADC0」「ADC1」... と書かれているピンを探しましょう。
AGND は「アナログ用のグラウンド」。デジタル回路の大きな電流が流れない経路になっています。

問いの答えと解説

  1. 両端が抵抗体の端、真ん中がワイパ（可動接点）です。両端を 3V3 と AGND に、真ん中を GP26（ADC0）につなぎます。回すと真ん中の電圧が 0〜3.3V で変化します（どちらの端を 3V3 にするかで回転方向が逆になるだけ）。
  2. GP26 = ADC0（pin31）、GP27 = ADC1（pin32）、GP28 = ADC2（pin34） の 3 本です。GP29（ADC3）は Pico 2 W では VSYS 電圧の測定と Wi-Fi チップの通信に使われています。
  3. AGND は基板上で ADC の近くを通るように配線された GND で、デジタル回路の電流によるノイズの影響が小さいからです（電気的には他の GND とつながっています）。
  4. ワイパの電圧が最大 5V になり、ADC 入力の上限 3.3V を超えます。RP2350 のデジタルピンは通電中なら 5V に耐えますが、ADC ピン（GP26〜29）は対象外で、壊れる恐れがあります。

⚠ ハマりどころ

  • 可変抵抗の脚はブレッドボードに浅くしか刺さらないことがあります。値が飛ぶ場合は接触不良を疑いましょう。
  • 3V3 と AGND を真ん中の脚にまたがってつなぐと、端まで回したときにショートします。必ず両端を電源に。

STEP 2コーディング課題

ADC で読んだ値を PWM の明るさに反映し、電圧もシリアルに表示します。

要件

  • ADC0 を 10ms ごとに読む
  • 直近 8 回の移動平均でノイズを減らす
  • 平均値に応じて GP15 の LED の明るさを PWM で変える（回したとき明るさが自然に変わるよう工夫する）
  • 200ms ごとに「生の値・電圧・デューティ」をシリアルに表示する
adc_init() → adc_gpio_init(26) → adc_select_input(0) → adc_read()（0〜4095）。CMake に hardware_adc を追加。
電圧 = raw × 3.3 / 4096。
PWM の TOP を 4095 にすると、ADC の値をそのままデューティに使えます。
移動平均は「リングバッファ + 合計値」。新しい値を足して一番古い値を引けば、毎回 8 個足し直す必要はありません。
直線的に明るさを変えると暗い側が急に変わって見えます。raw² / 4095 のような 2 乗カーブにすると自然です。

解説

  • adc_gpio_init() はピンのデジタル入力回路を切り離してアナログ専用にします。これを忘れると値が不安定になります。
  • 移動平均の合計は uint32_t で持ちます（4095×8 = 32760 は 16bit に収まりますが、平均数を増やしたときの保険）。
  • 2 乗カーブ avg * avg / 4095 は、uint32_t にキャストしてから掛け算しないと 16bit でオーバーフローします。

⚠ ハマりどころ

  • ADC の値は 0 や 4095 ぴったりにならないことがあります（オフセット誤差）。端の数カウントは「誤差の範囲」と割り切りましょう。
  • printf で %f を使うと少しコードが大きくなります。気になる場合は整数で mV 表示に。

✅ 動作確認

🚀 発展課題

  • 移動平均を指数移動平均（EMA） y += (x - y) / 8 に置き換え、メモリを 1 変数に減らす。
  • 内蔵温度センサ（ADC の最後のチャネル）も読み、チップ温度を表示する。
  • 可変抵抗の値で課題03の RGB LED の色相を操作する。
