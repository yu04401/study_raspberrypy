07反応速度ゲームを作ろう

割り込み・タイマ・ステートマシンという、組み込みソフトの骨格になる 3 つの技術を使います。トランジスタで大きめの負荷を動かす回路も設計します。

  • ⏱ 目安 120分
  • 🔧 回路 + 💻 コード
  • 📚 GPIO割り込み・アラーム・状態遷移・トランジスタ

🎯 つくるもの

赤 LED が点いてからランダムな時間（2〜5 秒）後に緑 LED とブザー。そこからボタンを押すまでの時間を ms で表示する反応速度ゲームを作ります。緑が点く前に押したら「フライング」です。

🧰 使う部品

  • タクトスイッチ×1
  • 赤色LED×1
  • 緑色LED×1
  • 抵抗 220Ω×2
  • アクティブブザー×1
  • NPN トランジスタ（S8050）×1
  • 抵抗 1kΩ×1
  • 整流ダイオード（任意）×1

共通で使うもの: Pico 2 W、ブレッドボード、ジャンパワイヤ、USB ケーブル。

📌 この課題のポイント

  • GPIO の電流は数 mA が目安。それ以上の負荷はトランジスタでスイッチする。
  • 割り込みを使うと、メインループが何をしていてもボタンの瞬間を逃さない。押した時刻は割り込みの中で記録する。
  • 割り込みとメインで共有する変数には volatile。割り込みハンドラは短く（printf・sleep 禁止）。
  • sleep で待つ代わりにアラーム（タイマ）を使い、待っている間もボタンを監視する。
  • 動作を状態（ステート）に分けて switch で書くと、複雑な動きでも見通しよく書ける。

STEP 1回路課題

LED とボタンはこれまでと同じです。今回の主役はブザーを鳴らすトランジスタ回路です。

  1. アクティブブザーは約 30mA 流れます。GPIO に直接つないで鳴らしてはいけない理由は？
  2. NPN トランジスタでブザーを ON/OFF する回路を考えよう。エミッタ(E)・ベース(B)・コレクタ(C)はそれぞれどこにつなぐ？
  3. ベース抵抗はキットの 220Ω / 1kΩ / 10kΩ のどれが適切？ トランジスタの電流増幅率 hFE = 100、ブザー 30mA として計算しよう。
  4. アクティブブザーとパッシブブザーの見分け方は？
  5. （任意）ブザーに並列に整流ダイオードを入れることがあります。なぜ？ 向きは？
GPIO の駆動能力の設定は 2〜12mA。チップ全体で流せる電流にも上限があります。
負荷（ブザー）の GND 側をトランジスタで切る「ローサイドスイッチ」が基本形です。E は GND 側。
必要なベース電流 IB = IC ÷ hFE。確実に ON（飽和）させるため、その 5〜10 倍流すのが定石。ベース抵抗の電圧は 3.3V − 0.7V（B-E 間の電圧）です。
S8050 は平らな面（文字のある面）を手前にして、左から E・B・C の順です（念のため刻印・データシートで確認）。
コイル（ブザーの中身）は電流を急に切ると高い電圧（逆起電力）を出します。

問いの答えと解説

  1. 30mA は GPIO の駆動能力（最大設定 12mA）を大きく超えます。電圧が下がって鳴らないだけでなく、ピンや IC を傷める原因になります。
  2. E → GND、C → ブザーの −、ブザーの + → 3V3、B → 抵抗 → GP10。GP10 を High にするとベース電流が流れ、C-E 間が ON になってブザーに電流が流れます。
  3. 必要な IB = 30mA ÷ 100 = 0.3mA。5〜10 倍で 1.5〜3mA が目標です。
    • 1kΩ: (3.3−0.7)/1k = 2.6mA → 最適
    • 220Ω: 11.8mA → GPIO に負担が大きすぎ
    • 10kΩ: 0.26mA → 足りず、ON しきらない（音が小さい・トランジスタが発熱）
  4. アクティブブザーは底面が樹脂で封止されていてシールが貼られていることが多く、直流をかけるだけで「ピー」と鳴ります。パッシブは底面に基板が見え、直流では「カチッ」としか鳴りません（PWM で音程を作る必要がある）。
  5. 電流を切った瞬間の逆起電力でトランジスタが傷むのを防ぎます。カソード（白帯）を + 側に、ブザーと並列に入れます（還流ダイオード）。
トランジスタで切り離しているので、ブザーの + を VBUS（5V）につないでも GPIO は安全です。そのほうが音は大きくなります。

⚠ ハマりどころ

  • E と C を逆にすると、ほとんど電流が流れず鳴りません（まったく鳴らないか、ごく小さい音）。
  • S8050 と似た見た目の PNP（S8550）を取り違えないように。刻印を確認しましょう。

STEP 2コーディング課題

状態遷移の図を見ながら、ステートマシンとして実装します。

要件

  • 状態を enum（IDLE / WAIT / GO / RESULT）で定義し、メインループの switch で処理する
  • ボタンはGPIO 割り込みで受け取り、押した時刻を割り込みの中で記録する
  • WAIT の 2〜5 秒（ランダム）は sleep ではなくアラームで待ち、待っている間に押されたらフライングにする
  • GO になったら緑 LED を点け、ブザーを 80ms 鳴らす
  • 反応時間（ms）とベスト記録をシリアルに表示する
gpio_set_irq_enabled_with_callback(pin, GPIO_IRQ_EDGE_FALL, true, &callback)。コールバックの引数は (uint gpio, uint32_t events)。
時刻は time_us_64()（起動からの µs）。割り込みでもチャタリングは起きるので、前回から 30ms 以内の割り込みは捨てます。
add_alarm_in_ms(ms, callback, NULL, true) で 1 回だけのタイマ。戻り値の ID を cancel_alarm(id) に渡せば取り消せます。コールバックが 0 を返すと繰り返しません。
乱数は #include "pico/rand.h" の get_rand_32()（CMake に pico_rand）。
割り込みでは「フラグを立てるだけ」にして、表示などの重い処理はメインループで行います。

解説

  • 時刻は割り込みの中で取るのがポイント。メインループで押下に気づいた時刻を使うと、ループの遅れぶんだけ記録が悪くなります。GO の時刻も同様にアラームのコールバックで記録しています。
  • take_press() で「読んだらフラグを下ろす」を 1 か所にまとめています。状態をまたいで押下が残ると、RESULT 中の押下が次のゲーム開始に化けてしまうためです。
  • メインループは一度もブロックしない（フライング時の beep を除く）ので、どの状態でも即座に反応できます。

⚠ ハマりどころ

  • 割り込みハンドラの中で printf や sleep_ms を呼ぶと、固まったり他の割り込みが遅れたりします。
  • volatile を付け忘れると、最適化でメインループが変数の変化に気づかないことがあります（-O2 で再現しやすい）。
  • cancel_alarm の直前にアラームが発火していた場合に備えて、フライング時は緑 LED も消しています。

🚀 発展課題

  • 5 回の平均タイムを出す。最高記録を電源を切っても残す（フラッシュ書き込み: 上級）。
