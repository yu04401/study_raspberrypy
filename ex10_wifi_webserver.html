10Wi-FiでスマホからLEDを操作

Pico 2 W ならではの Wi-Fi を使い、ブラウザから LED を操作できる小さな Web サーバを作ります。

  • ⏱ 目安 150分
  • 🔧 回路 + 💻 コード
  • 📚 CYW43・lwIP(TCP)・HTTP・コールバック駆動

🎯 つくるもの

同じ Wi-Fi につないだスマホのブラウザで Pico の IP アドレスを開くと、LED の状態とチップ温度が表示され、ON / OFF のリンクで LED を操作できるようにします。手元のボタンで切り替えた状態もページに反映します。

🧰 使う部品

  • 赤色LED×1
  • 抵抗 220Ω×1
  • タクトスイッチ×1

共通で使うもの: Pico 2 W、ブレッドボード、ジャンパワイヤ、USB ケーブル。回路は課題02と同じです。2.4GHz 帯の Wi-Fi が必要です。

📌 この課題のポイント

  • Pico 2 W の Wi-Fi は CYW43439 という別チップ。RP2350 とは内部の SPI でつながっている。
  • TCP/IP 処理は lwIP ライブラリ。設定ファイル lwipopts.h を自分で用意する。
  • lwIP の raw API はコールバック駆動。「接続された」「受信した」「送信できた」ときに関数が呼ばれる。
  • poll モードなら、ネットワーク処理はメインループの cyw43_arch_poll() の中で動くので、排他制御を考えなくてよい。
  • パスワードはソースに直書きせず、ビルド時に渡す。

STEP 1回路課題

回路そのものは課題02と同じです。Pico 2 W 特有の注意点を確認しましょう。

  1. Pico 2 W で、ユーザーが自由に使えない（基板の外に出ていない、または内部で使われている）GPIO はどれ？ 何に使われている？
  2. 基板上の LED はどこにつながっている？
  3. PC につながずに USB 充電器やモバイルバッテリーで動かすと、printf の IP アドレスが見えません。IP アドレスを知る方法を考えよう。
回路図（Pico 2 W のデータシート）で「WL_」で始まる信号を探してみましょう。
課題01で使った CYW43_WL_GPIO_LED_PIN がヒントです。

問いの答えと解説

  1. GP23・GP24・GP25・GP29 は Wi-Fi チップとの接続に使われています（GP23 = 電源 ON、GP24 = データ/割り込み、GP25 = チップセレクト、GP29 = クロック兼 VSYS 電圧測定）。基板の外にも出ていません。
  2. CYW43439 の WL_GPIO0 です。RP2350 からは直接触れず、Wi-Fi チップに「LED を点けて」と頼む形になります。
  3. 例: ①ルーターの管理画面で DHCP の割り当て一覧を見る、②課題09の LCD に IP アドレスを表示する、③ルーターで IP を固定（DHCP 予約）する、④mDNS で pico.local のような名前でアクセスする（発展）。
Wi-Fi 送信時は電流が一瞬増えます。サーボなど大電流の部品と同時に使う場合は、課題06のように電源を分けると安定します。

⚠ ハマりどころ

  • 5GHz 帯の SSID には接続できません（2.4GHz のみ）。
  • ゲスト Wi-Fi など「端末間通信を禁止」している SSID だと、スマホから Pico に届きません。

STEP 2コーディング課題

Wi-Fi 接続 → TCP サーバ起動 → リクエストに応じて HTML を返す、の流れで作ります。

要件

  • SSID / パスワードは CMake のオプションで渡す（ソースに書かない）
  • DHCP で IP アドレスを取得し、シリアルに表示する。接続できたら基板上 LED を点灯
  • ポート 80 で待ち受け、/ で状態表示、/on /off で LED を操作する
  • ページにはチップ内蔵温度センサの値も表示する
  • 物理ボタンでも LED をトグルでき、ページを更新すると反映される
  • pico_cyw43_arch_lwip_poll（poll モード）で作る
Wi-Fi: cyw43_arch_init() → cyw43_arch_enable_sta_mode() → cyw43_arch_wifi_connect_timeout_ms(ssid, pass, CYW43_AUTH_WPA2_AES_PSK, 30000)。IP は ip4addr_ntoa(netif_ip4_addr(netif_list))。
lwIP の TCP サーバの流れ: tcp_new_ip_type → tcp_bind → tcp_listen_with_backlog → tcp_accept。接続ごとに tcp_recv / tcp_sent / tcp_err のコールバックを登録します。
受信コールバックで p == NULL は「相手が切断した」。データを読んだら tcp_recved() でウィンドウを開け、pbuf_free() で解放します。
応答は tcp_write() → tcp_output()。全部届いたら（tcp_sndqueuelen() が 0）tcp_close()。
HTTP の応答は「ステータス行 + ヘッダ + 空行 + 本文」。Content-Length と Connection: close を付けると簡単です。
内蔵温度センサ: adc_set_temp_sensor_enabled(true)、入力は NUM_ADC_CHANNELS - 1。温度 = 27 − (V − 0.706) / 0.001721。
poll モードではメインループで cyw43_arch_poll() を呼び続けないと何も起きません。

解説

ビルド時に SSID とパスワードを渡します（ビルドフォルダで）:

  • コールバックの戻り値のルール: コールバックの中で tcp_abort() したら必ず ERR_ABRT を返します。返さないと解放済みのメモリを lwIP が触ってクラッシュします。
  • tcp_err が呼ばれた時点で pcb は解放済み。そこで pcb を触ってはいけません。
  • TCP_WRITE_FLAG_COPY を付けると lwIP がデータをコピーするので、関数を抜けて消えるスタック上の配列（body）を渡しても安全です。
  • poll モードではネットワークのコールバックもメインループの中（cyw43_arch_poll() の中）で動くので、g_led を割り込みと取り合う心配がありません。pico_cyw43_arch_lwip_threadsafe_background に切り替えると割り込みで動くようになり、cyw43_arch_lwip_begin() / end() による排他が必要になります。

⚠ ハマりどころ

  • lwipopts.h が見つからないとビルドエラーになります。target_include_directories を忘れずに。
  • SSID / パスワードは build/CMakeCache.txt に平文で残ります。build フォルダを Git に入れないこと。
  • ブラウザは /favicon.ico も要求してきます。今回のコードは何を聞かれても同じページを返すので問題ありませんが、本格的には 404 を返しましょう。

✅ 動作確認

🚀 発展課題

  • /api/status で JSON（{"led":true,"temp":28.5}）を返し、ページ側は JavaScript の fetch で 1 秒ごとに自動更新する。
  • 課題09の DHT11 の温湿度を表示する（スマホから見られる温湿度計）。
  • アクセスポイントモード（cyw43_arch_enable_ap_mode）にして、ルーターなしでスマホと直接つなぐ。
  • threadsafe_background モードに書き換え、排他制御を正しく入れる。
