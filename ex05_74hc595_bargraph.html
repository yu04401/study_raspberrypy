05シフトレジスタでLEDバーグラフ

74HC595 を使って、たった 3 本の GPIO で 8 個の LED を制御します。データシートを読む練習も兼ねます。

  • ⏱ 目安 90分
  • 🔧 回路 + 💻 コード
  • 📚 シリアル→パラレル変換・クロック/ラッチ・パスコン

🎯 つくるもの

可変抵抗の値に応じて LED バーグラフが下から 0〜8 個点灯する「レベルメーター」を作ります。

🧰 使う部品

  • 74HC595（Serial to Parallel Chip）×1
  • LED バーグラフ×1
  • 抵抗 220Ω×8
  • セラミックコンデンサ 0.1µF×1
  • 可変抵抗 10kΩ×1

共通で使うもの: Pico 2 W、ブレッドボード、ジャンパワイヤ、USB ケーブル。可変抵抗は課題04と同じ配線（GP26）です。

📌 この課題のポイント

  • 74HC595 は 1bit ずつ送られてきたデータを 8bit 並列に出力する IC。GPIO を節約できる。
  • 「シフトクロックでデータを押し込む」と「ラッチで出力に反映する」が分かれているので、送信途中の状態が LED に見えない。
  • IC の電源ピンの近くには 0.1µF のパスコン（バイパスコンデンサ）を置くのが鉄則。
  • 名前の上に線（/OE, /MR）があるピンは負論理（Low で有効）。

STEP 1回路課題

74HC595 の配線はピン数が多いので、まずピン配置を把握するところから始めましょう。

  1. 74HC595 の切り欠き（半円マーク）を左にしたとき、1 番ピンはどこ？ ピン番号はどう数える？
  2. 次のピンはそれぞれどこにつなぐ？ VCC(16) / GND(8) / DS(14) / SH_CP(11) / ST_CP(12) / /OE(13) / /MR(10) / Q0〜Q7
  3. /OE と /MR は負論理です。普段どおり動かすには、それぞれ High と Low のどちらに固定する？
  4. 0.1µF のコンデンサはどこに置く？ 何のため？
  5. 8 個全部点けたとき、74HC595 全体に流れる電流は約何 mA？ 74HC595 の VCC/GND の許容電流（最大 70mA）に収まる？
DIP の IC は、切り欠きを左にして左下が 1 番。そこから反時計回りに 1→8（下の列）、9→16（上の列）と数えます。
/OE = Output Enable（出力を有効にする）、/MR = Master Reset（中身をクリアする）。それぞれ「有効」にしたいか「無効」にしたいかを考えます。
IC は内部が切り替わる瞬間に電源から急に電流を引き込みます。そのとき電源電圧が一瞬下がるのを防ぐのがパスコンです。
LED 1 個あたりの電流は課題01で計算済み（220Ω で約 5.9mA）。

問いの答えと解説

  1. 切り欠きを左にして左下が 1 番。下の列を左から右へ 1〜8、上の列を右から左へ 9〜16 と反時計回りに数えます（上の回路図の並びと同じ）。
  2. 上の回路図のとおりです。VCC → 3V3、GND → GND、DS → GP18、ST_CP → GP19、SH_CP → GP20、Q0〜Q7 → 220Ω → バーグラフの各 LED → GND。
  3. /OE は Low（GND）で出力が常に有効、/MR は High（3V3）でリセットしない状態にします。逆にすると「何も出ない」「すぐ消える」になります。
  4. VCC(16) と GND の間、IC のできるだけ近くに置きます。出力が一斉に切り替わる瞬間の電源電圧の落ち込み（ノイズ）を吸収し、誤動作を防ぎます。
  5. 1 個約 5〜6mA × 8 個 ≒ 40〜47mA。70mA 以内なので OK です。バーグラフは 10 本ありますが、9・10 本目は使いません。
74HC シリーズは 2〜6V で動くので 3.3V 駆動で問題ありません（74HCT は 4.5V 以上が必要なので不可）。バーグラフの向き（どちらがアノードか）は、1 本ずつ 3V3 → 220Ω で当てて確認しましょう。

⚠ ハマりどころ

  • IC を逆向きに差すと電源が逆接続になり、熱くなって壊れます。通電前に切り欠きの向きを必ず確認。
  • VCC と /MR、GND と /OE のつなぎ忘れが最も多いミスです。何も光らなければここから確認。
  • 配線が多いので、ジャンパワイヤの色を「電源=赤、GND=黒、信号=その他」と決めておくとデバッグが楽です。

STEP 2コーディング課題

74HC595 に 1 バイト送る関数を作り、可変抵抗の値でレベルメーターを表示します。

要件

  • hc595_write(uint8_t data) を作る（bit0 → Q0 … bit7 → Q7）
  • 起動時に LED を 1 個ずつ流して配線を確認できるようにする
  • ADC の値（0〜4095）を 0〜8 段階に変換し、下から n 個点灯させる
  • 段階が変わったときだけ 74HC595 を更新する
送信手順: ① DS に 1bit 出す → ② SH_CP を High→Low（立ち上がりで取り込み）。これを 8 回繰り返し、最後に ③ ST_CP を High→Low で出力に反映。
MSB（bit7）から送ると、最後に送った bit0 が Q0 に来ます。
下から n 個点灯するビットパターンは (1 << n) - 1。n=3 なら 0b00000111。
0〜4095 を 0〜8 の 9 段階にするには raw * 9 / 4096。

解説

  • このように GPIO を手で上げ下げして通信することをビットバンギングと言います。busy_wait_us(1) は念のための待ちで、74HC595 自体はもっと速く動けます。
  • ラッチがあるおかげで、8bit を送っている途中のでたらめなパターンは LED に現れません。ラッチを毎ビット叩くとどう見えるか、試してみると理解が深まります。
  • 「変化したときだけ更新」は、無駄な通信を減らす組み込みの定番テクニックです。

⚠ ハマりどころ

  • level = 8 のとき (1u << 8) - 1 = 255 です。uint8_t で 1 << 8 を計算すると 0 になるので、1u（32bit）で計算してからキャストします。
  • LED の点灯順が逆なら、送る順（MSB/LSB）か、バーグラフの配線順が逆です。

✅ 動作確認

🚀 発展課題

  • ピークホールド: 一番高かった位置の LED だけ 1 秒間残す。
  • ナイトライダー（左右に往復する光）を作る。
  • ビットバンギングをハードウェア SPI（spi_write_blocking）に置き換える。SCK と TX に使えるピンを調べ、配線を考え直そう。
  • Q7' から 2 個目の 74HC595 につなげば 16 本制御できる（デイジーチェーン）。どう送ればよいか考えよう。
