06ジョイスティックでサーボを動かす

サーボモータの PWM 制御と、5V で動く部品との付き合い方を学びます。

  • ⏱ 目安 90分
  • 🔧 回路 + 💻 コード
  • 📚 サーボPWM・電源設計・キャリブレーション

🎯 つくるもの

ジョイスティックを左右に倒すと、倒した量に比例した速さでサーボが回るようにします。スティックを押し込むと 90° に戻ります。

🧰 使う部品

  • サーボ（SG90）×1
  • ジョイスティック×1
  • 電解コンデンサ 10µF×1

共通で使うもの: Pico 2 W、ブレッドボード、ジャンパワイヤ、USB ケーブル。

📌 この課題のポイント

  • サーボは 50Hz（20ms 周期）のパルスの幅で角度を決める。0.5ms ≒ 0°、2.4ms ≒ 180°（個体差あり）。
  • モータは動き出しに大電流を引く。電源は 5V（VBUS）から取り、GND は共通にする。
  • ジョイスティックは中身が可変抵抗 2 個 + スイッチ。3.3V で使う（ADC は 3.3V まで）。
  • アナログスティックの中心値は個体ごとに違う。起動時のキャリブレーションとデッドゾーンで吸収する。

STEP 1回路課題

サーボは 5V、ジョイスティックは 3.3V と、電源が 2 系統になります。どこから取るかを考えましょう。

  1. サーボの 3 本の線（茶・赤・橙）は、それぞれ何の線？
  2. サーボの電源（赤）は 3V3（pin36）と VBUS（pin40）のどちらにつなぐ？ 理由は？
  3. ジョイスティック基板には「+5V」と書かれていることがあります。VCC は 3V3 と VBUS のどちらにつなぐべき？ 理由は？
  4. 10µF の電解コンデンサはどこに、どの向きで入れる？ 何のため？
  5. サーボの信号線を Pico の 3.3V 出力で直接駆動してよい？
SG90 の定格は 4.8〜6V。動き出しの瞬間には数百 mA 流れることがあります。3V3 ピンから取れる電流は 300mA 程度が目安です。
ジョイスティックの出力（VRx/VRy）は、VCC をつないだ電圧の範囲で動きます。
電解コンデンサには極性があります。白い帯・短い脚が −。

問いの答えと解説

  1. 茶 = GND、赤 = 電源(+)、橙 = 信号（PWM）です。
  2. VBUS（5V）。SG90 は 4.8V 以上が定格で、3.3V ではトルク不足・不安定になります。また動き出しの大電流で 3.3V レギュレータの電圧が下がり、Pico 自体がリセットする原因になります。VBUS は USB の 5V がそのまま出ているピンです（USB 給電時のみ）。
  3. 3V3。5V で給電すると VRx/VRy が最大 5V になり、ADC 入力の上限 3.3V を超えます（ADC ピンは 5V に耐えられません）。可変抵抗なので 3.3V でも問題なく動きます。
  4. サーボの電源（VBUS と GND の間）に、+ を VBUS、−（白帯）を GND 向きで入れます。モータの動き出しの電流を手元から供給して、電源電圧の落ち込みを和らげます。逆に挿すと破損・破裂の危険があります。
  5. 多くの SG90 は 3.3V の信号で動きます（入力の High 判定が 2V 前後のため）。動作が不安定な個体なら、トランジスタ（課題07）で 5V に変換します。
サーボ 1 個なら PC の USB ポートからの給電で動きますが、2 個以上や大きなサーボは別電源を用意し、GND だけ Pico と共通にします。GND が共通でないと信号の基準がずれて動きません。

⚠ ハマりどころ

  • サーボが動くたびに Pico が再起動する → 電源不足です。コンデンサを追加するか別電源に。
  • サーボを手で無理に回すとギアが欠けます。
  • 角度の端（0° / 180°）でサーボが「ジー」と鳴り続けるなら、パルス幅が可動範囲の外です。PULSE_MIN_US / PULSE_MAX_US を狭めましょう。

STEP 2コーディング課題

スティックの傾きで速度を決める（位置ではなく速度で制御する）方式で作ります。

要件

  • GP16 に 50Hz の PWM を出し、1 カウント = 1µs になるように設定する
  • 角度（0〜180°）→ パルス幅（500〜2400µs）に変換する関数を作る
  • 起動時にスティックの中央値を自動で測る（キャリブレーション）
  • 中央 ±200 カウントは反応しない（デッドゾーン）
  • 傾きに比例した速度で角度を増減させ、0〜180° の範囲に制限する
  • スティック押し込みで 90° に戻す
1µs 単位にするには、分周比 = システムクロック ÷ 1MHz。clock_get_hz(clk_sys) / 1000000.0f で計算すると、クロックが変わっても正しく動きます（hardware/clocks.h）。
TOP = 20000 − 1 にすれば 20ms 周期。pwm_set_gpio_level(pin, パルス幅[µs]) とそのまま書けます。
角度は float で保持し、20ms ごとに「速度」を足していきます。整数だと遅い速度が 0 に丸められてしまいます。
中央値は 32 回ほど読んで平均します。そのときスティックには触らないこと。

解説

  • デッドゾーンの外側だけを 0〜1 に正規化しているので、デッドゾーンを抜けた直後からなめらかに速度が上がります（単純に dx を使うと、抜けた瞬間に急に動き出します）。
  • 中央値は左右で非対称なことが多いので、span を左右別々に計算しています。
  • 「位置」ではなく「速度」で操作する方式は、ラジコンやクレーンのような実機の操作感に近くなります。

⚠ ハマりどころ

  • pwm_config_set_clkdiv の最大値は 255.94。150 は範囲内ですが、もっと遅いクロックを作りたいときは TOP 側で調整します。
  • abs() を使うときは <stdlib.h> を include。

✅ 動作確認

🚀 発展課題

  • Y 軸でもう 1 台のサーボを動かし、パン・チルト台を作る（電源容量に注意）。
  • 急停止・急発進しないよう加減速（速度に上限付きの変化率）を入れる。
  • スティック位置をそのまま角度にする「位置制御モード」と切り替えられるようにする。
