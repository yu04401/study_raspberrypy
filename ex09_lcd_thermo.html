09LCD付き温湿度計

I2C 通信で LCD を動かし、µs 単位のタイミングが命の DHT11 をビットバンギングで読み取ります。

  • ⏱ 目安 120分
  • 🔧 回路 + 💻 コード
  • 📚 I2C・LCD制御・独自プロトコル・割り込み禁止区間

🎯 つくるもの

DHT11 で温度と湿度を測り、LCD1602 の 1 行目に温度、2 行目に湿度を表示します。2 秒ごとに更新します。

🧰 使う部品

  • LCD1602 モジュール（I2C 変換基板付き）×1
  • 温湿度センサ（DHT11）×1
  • 抵抗 10kΩ×1

共通で使うもの: Pico 2 W、ブレッドボード、ジャンパワイヤ、USB ケーブル。

📌 この課題のポイント

  • I2C は SDA（データ）と SCL（クロック）の 2 本で複数の機器をつなげる通信。機器はアドレスで区別する。
  • I2C の線は「Low に引くだけ」（オープンドレイン）。High にするのはプルアップ抵抗の役目。
  • LCD の I2C 基板（PCF8574）は、I2C で受けた 8bit を LCD の端子に出しているだけ。LCD 本体は4bit モードで動かす。
  • DHT11 は独自の 1 線式プロトコル。High の長さ（約 27µs か 70µs）で 0/1 を表すので、読み取り中は割り込みを止める。
  • 受信データはチェックサムで検証する。

STEP 1回路課題

LCD を I2C0（GP4 / GP5）に、DHT11 を GP2 につなぎます。電源電圧の選び方が今回の要です。

  1. RP2350 の I2C は好きなピンで使える？ I2C0 の SDA/SCL に使える GPIO の組を挙げよう。今回使う GP4 / GP5 の物理ピン番号は？
  2. I2C にプルアップ抵抗が必要なのはなぜ？
  3. LCD の I2C 基板には SDA/SCL のプルアップ抵抗（4.7kΩ 程度）が載っていて、モジュールの VCC につながっています。モジュールを 5V で動かすと、Pico 側の SDA/SCL はどうなる？ どうするのが安全？
  4. DHT11 の脚は 4 本（素子単体の場合）。どの脚をどこにつなぐ？ データ線にはプルアップが必要？
I2C0 の SDA は GP0, 4, 8, 12, 16, 20、SCL はそれぞれ +1 の GPIO です。
どの機器も線を Low に「引く」ことしかできないので、誰も引いていないときに High に戻す仕組みが必要です。
プルアップ抵抗はつながっている VCC の電圧まで線を引き上げます。課題08の「5V トレラント」の条件を思い出しましょう。
DHT11（格子面を手前）: 左から 1 = VCC、2 = DATA、3 = 未使用、4 = GND。3 ピンの基板付きモジュールなら印字に従います。

回路図

問いの答えと解説

  1. 決められた組み合わせの中から選べます。I2C0 は SDA = GP0/4/8/12/16/20、SCL = GP1/5/9/13/17/21。GP4 = 物理ピン6、GP5 = 物理ピン7です。
  2. I2C は複数の機器が同じ線を共有するため、どの機器も「Low に引く」か「手を離す」しかできません（オープンドレイン）。手を離したときに線を High に戻すのがプルアップ抵抗です。これで 2 台が同時に送信してもショートしない仕組みになっています。
  3. SDA/SCL が5V まで引き上げられます。GP4/GP5 はデジタルピンなので通電中なら耐えますが、Pico の電源が入る前に LCD 側に 5V が来ると保護されません。まずは 3.3V で動かすのがおすすめです。文字が薄い・見えないときは、基板裏の青い半固定抵抗（コントラスト）を回します。それでも見えない LCD の場合だけ 5V 給電にし、本来はレベル変換モジュールを挟みます。
  4. VCC → 3V3、DATA → GP2、GND → GND、3 番は未接続。DATA は I2C と同じくセンサが Low に引く方式なのでプルアップが必要です（10kΩ を 3V3 へ。基板付きモジュールは内蔵）。

⚠ ハマりどころ

  • LCD に何も表示されない原因の 1 位はコントラスト、2 位はI2C アドレス違い（0x27 と 0x3F が多い）です。
  • バックライトは点くのに文字がない → 初期化シーケンスの失敗か、コントラストです。
  • SDA と SCL の取り違え。I2C スキャンで何も見つからないときはまず入れ替えてみましょう。

STEP 2コーディング課題

①I2C スキャンでアドレスを確認 → ②LCD に文字を出す → ③DHT11 を読む、の順で少しずつ作りましょう。

要件

  • 起動時に I2C バスをスキャンし、見つかったアドレスをシリアルに表示する
  • PCF8574 経由で LCD を 4bit モードで初期化し、任意の位置に文字列を表示する関数を作る
  • DHT11 からデータを読む関数を作る。チェックサムが合わなければ失敗とする
  • 時間に厳しい受信部分は割り込み禁止にする
  • 2 秒ごとに LCD の 1 行目に温度（°C）、2 行目に湿度（%）を表示する
I2C: i2c_init(i2c0, 100000)、gpio_set_function(pin, GPIO_FUNC_I2C)、i2c_write_blocking(i2c0, addr, &data, 1, false)。スキャンは各アドレスに 1 バイト読みを試し、戻り値が 0 以上なら存在します。
PCF8574 の 8bit と LCD の対応: P0 = RS、P1 = RW（常に 0）、P2 = EN、P3 = バックライト、P4〜P7 = データ D4〜D7。
LCD に 4bit を渡す手順: 「データ + EN=1」を書く → 「データ + EN=0」を書く（EN の立ち下がりで取り込まれる）。1 バイトは上位 4bit → 下位 4bit の 2 回で送ります。
LCD 初期化: 0x3 を 3 回 → 0x2（4bit モードへ）→ 0x28 → 0x0C → 0x06 → 0x01（クリア、2ms 待つ）。
DHT11: ① GP2 を 18ms 以上 Low → ② 入力に戻す → ③ センサが 80µs Low・80µs High で応答 → ④ 40bit（各ビット: 50µs Low の後、High が 26〜28µs なら 0、70µs なら 1）。データは 湿度整数, 湿度小数, 温度整数, 温度小数, チェックサム の 5 バイト。
割り込み禁止は uint32_t s = save_and_disable_interrupts(); … restore_interrupts(s);（hardware/sync.h）。

解説

  • DHT11 のビット判定は「High の長さが 40µs より長いか」。0（約 27µs）と 1（約 70µs）のちょうど中間をしきい値にすると、多少のずれに強くなります。
  • 割り込み禁止区間は約 4ms（40bit × 約 100µs）。USB の処理がその間止まりますが、この程度なら問題ありません。禁止区間はできるだけ短くが原則なので、18ms のスタート信号は禁止区間の外に出しています。
  • LCD の行末までスペースで埋めて表示しているので、前の表示の文字が残りません（クリアコマンドは遅くてちらつくため使わない）。
  • 0xDF は LCD の文字コード表（CGROM）での「°」です。LCD は UTF-8 を理解しないので、日本語や記号は文字コード表で探します。

⚠ ハマりどころ

  • DHT11 は 1 秒に 1 回より速く読むと失敗します。
  • i2c_write_blocking の戻り値が PICO_ERROR_GENERIC なら、そのアドレスに機器がいません（アドレス違い・配線ミス）。
  • printf を割り込み禁止区間の中で呼ぶと固まることがあります。
